# Entropy Runtime v3.0 — 路线图

> 版本: v3.0 (计划)
> 基线: v2.1 (当前，2026-06-01)
> 状态: 规划中

---

## v3 核心目标

**从「被动防御」升级为「主动免疫」** — 不再依赖规则匹配拦截危险，而是让系统在架构层面无法被利用。

---

## Phase 1: 架构级安全重构 (2周)

### 1.1 统一输入解码层 (P1)
**现状**: verification.py 和 security.py 各自实现 `_decode_preprocess()`，逻辑重复。
**目标**: 抽取 `security/preprocessor.py` 统一导入，Pydantic 模型强制类型校验。
**工作量**: 2天
**依赖**: 无

### 1.2 Pydantic 模型层 (P1)
**现状**: routes/runtime_api.py 和 routes/agent_api.py 通过裸 `data.get()` 提取请求参数。
**目标**: 为每个端点创建 Pydantic Request/Response 模型，类型校验自动化。
**工作量**: 3天
**依赖**: 1.1

### 1.3 Healthcheck 安全加固 (P1)
**现状**: subprocess 调用外部脚本，无校验。
**目标**: (1) os.stat + os.access 验证脚本 ownership/permission，(2) Python fallback healthcheck。
**工作量**: 1天
**依赖**: 无

### 1.4 速率限制与连接管理 (P1)
**现状**: SSE 流式端点无连接数限制，/api/chat 无速率限制。
**目标**: (1) 最大并发 SSE 连接数 (默认 10)，(2) 滑动窗口速率限制 (60 req/min)。
**工作量**: 2天
**依赖**: 无

## Phase 2: 智能安全层 (3周)

### 2.1 动态信号图谱 (P2)
**现状**: VERIFICATION_RULES 和 INTENT_SIGNALS 是静态配置。
**目标**: 引入动态信号图谱——基于运行时统计（常见绕过模式、攻击向量频率）自动调整 blocked_signals 权重和顺序。
**工作量**: 5天
**依赖**: Phase 1

### 2.2 变异引擎 v3 — AI 辅助模糊测试 (P1)
**现状**: 变异引擎 v2 仅做 5 种固定编码变换。
**目标**: 接入 DeepSeek 生成上下文感知的变种：保留语义但改变语法结构（如 `rm -rf /` → `find / -type f -delete`）。
**工作量**: 5天
**依赖**: 无

### 2.3 行为基线建模 (P2)
**现状**: 无异常检测，仅做规则匹配。
**目标**: 对每个会话建立正常行为基线（工具调用频率、档位切换模式、输出格式），偏离基线触发告警。
**工作量**: 7天
**依赖**: Phase 1

### 2.4 多档位协同梯度防御 (P2)
**现状**: 档位独立工作，EMBRACE→EXPLORE→ADAPT→LET_GO 是线性升级。
**目标**: 引入「档位组合」模式——不同安全层可在不同档位独立运行，例如输入校验走 GEAR 3 规则但输出校验走 GEAR 1 规则。
**工作量**: 4天
**依赖**: 2.1, 2.3

---

## Phase 3: 可观测性与工具链 (2周)

### 3.1 红队 Dashboard (P2)
**现状**: 红队测试结果仅存 JSON，无可视化。
**目标**: (1) Web Dashboard 显示通过率趋势，(2) 每个绕过模式的实时热力图，(3) 变异谱系树可视化。
**工作量**: 5天
**依赖**: Phase 2

### 3.2 测试覆盖率追踪 (P2)
**现状**: 无法知道哪些安全路径未被覆盖。
**目标**: (1) 代码插桩追踪每条安全规则的命中次数，(2) 自动生成未覆盖的绕过路径推荐测试用例。
**工作量**: 3天
**依赖**: 2.2

### 3.3 自动化回归管道 (P2)
**现状**: 红队测试需手动触发。
**目标**: (1) GitHub CI 或 Cron 定时触发全量测试，(2) 回归失败自动回滚+告警，(3) 每次释出版本报告。
**工作量**: 2天
**依赖**: 3.1, 3.2

---

## Phase 4: 生态与集成 (2周)

### 4.1 MessageBoard v3 (P3)
**现状**: 多 Agent 通信通过 MemoryStore 实现，无独立通信层。
**目标**: 独立 MessageBoard service，支持 (1) 消息路由（by agent_id），(2) 消息过期 TTL，(3) 订阅制通知。
**工作量**: 4天
**依赖**: Phase 1

### 4.2 外部审计集成 (P3)
**目标**: 导出审计链为标准格式（如 CEF、LTSV），对接 SIEM 工具（ELK、Splunk）。
**工作量**: 3天
**依赖**: Phase 1

### 4.3 Hermes Agent 深度集成 (P3)
**目标**: Entropy Runtime 作为 Hermes Agent 的安全网关插件，所有 Hermes 调用自动经过安全层。
**工作量**: 5天
**依赖**: Phase 1, Phase 2

## 已知风险

1. **DeepSeek API 可用性** — AI 生成依赖外部 API，断网时退化到模板模式
2. **性能开销** — 解码预处理增加延迟 (~5ms/次)，基线建模需存储 (~100KB/会话)
3. **误报率** — 行为基线可能产生误报，需要调优期（~1周 shadow mode）

### v3.1 改进方向

1. **动态模板生成** — `_template_candidates` 基于 `target_context.focus_areas` 动态选择模板（CSRF/XSS/Auth 等）
2. **Fitness 路径可配置** — 根据每个 seed 的 `endpoint_type` 发送到正确路径
3. **CSRF 种子库** — 补充 CWE-352 CSRF 绕过种子（无 token / stale token / same-site bypass 等）
